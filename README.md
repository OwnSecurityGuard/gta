# GTA

**Game Debug Automation Platform**

Capture real game traffic → decode with hot-swappable plugins → replay and automate the session to debug.
All of it over MCP, so your AI agent drives the debugging loop.

GTA turns raw game-network traffic into structured, agent-queryable debug telemetry: packets are captured live (or replayed from `.pcap`), decoded by independent plugin processes, and assembled into a **debug trace** — request/response pairs, state changes, and causal chains (OpenTelemetry-style `TraceContext`). An agent can even use GTA to scaffold, build, and verify its own decoder plugin.

## Features

- **📡 Live capture & replay** — per-port pcap capture or offline `.pcap` replay; concurrent sessions with per-project plugin binding.
- **🧩 Hot-swappable decoder plugins** — every plugin is an independent process over gRPC: hot-load, hot-swap on a *running* session (`set_session_plugin`), crash-isolated from the pipeline.
- **🧭 Session timeline (debug trace)** — `get_session_timeline` builds the full request/response tree for a capture session from `TraceContext` (causation = parent, correlation = conversation). This is the **"capture once, see the whole flow"** MVP view. `trace_protocol_flow` drills into one behavior's chronological causation chain.
- **📊 Real-time aggregation** — sliding-window metrics declared in [`rules.yaml`](docs/rules-authoring.md) and queried with expr (`aggregate_query`).
- **🤖 Agent-driven plugin development** — `create_plugin` → `build_plugin` → `activate_plugin` → `verify_plugin` with automated failure attribution (`explain_plugin`); the contract and dev guide are served to agents via `get_plugin_contract` / `get_plugin_dev_guide`.
- **🎯 Behavior windows** — mark a user operation (`begin_capture_run` … `end_capture_run`) and get its chronological causation chain (`trace_protocol_flow`).
- **🔒 Physical dev/prod isolation** — all plugin-dev powers live in an optional Developer Plane; production just never starts that process. Not a feature flag — a missing process.

## Architecture

Three planes, split so **MCP stays a pure adapter** — `gta-mcp` spawns no subprocesses, writes no files, does no failure attribution; it only forwards. Filesystem and process powers live one plane down, so a production deployment that never starts the Developer Plane has *zero* dev-capability exposure.

```
Team member host                    AI Agent (Claude / DeepSeek / …)
┌──────────────────────┐                  │  MCP over HTTP — :8781  (/sse + /message · /mcp)
│  gta-agent           │                  │  Authorization: Bearer <token>
│  ├─ capture ingest ──┼── :9092 ──┐      ▼
│  └─ plugin tunnel ───┼── :9091 ─┐┌─────────────────────────────────────────────┐
└──────────────────────┘          ││  gta-mcp (:8781) — pure adapter: zero exec  │
                                  ││  Bearer auth via GTA_AUTH_TOKENS            │
┌─────────────────────────────────▼─────────┬───┴─────────────────────────────┐
│  Developer Plane                          │  Runtime Plane — gta-pipeline   │
│  gta-plugin-dev                           │  capture → decode → project     │
│  scaffold / build /                       │  → SQLite · PluginRegistry      │
│  activate / explain                       │  :9091 · AgentIngest :9092      │
│  (prod: never started)                    └───────────────┬─────────────────┘
└──────┼────────────────────────────────────────────────────┤ gRPC register + heartbeat
       │ launch binary, inject                              │ (observed, never managed)
       │ GTA_REGISTRY_ADDR                                  ▼
       └──────────►  decoder plugin processes ◄────────────┘
```

| Port | What listens |
|------|--------------|
| `:8781` | gta-mcp HTTP — `/sse` + `/message` (SSE) · `/mcp` (Streamable HTTP) · `/events/plugins` — Bearer-auth when `GTA_AUTH_TOKENS` is set |
| `:9888` | CaptureControl gRPC — gta-mcp → gta-pipeline |
| `:9091` | PluginRegistry gRPC — decoder plugins → gta-pipeline (remote members register through the gta-agent tunnel) |
| `:9092` | AgentIngest gRPC — gta-agent pushes raw frames from a team member's machine |
| `:8089` | PluginDev gRPC — only when the Developer Plane runs standalone (default: embedded at `127.0.0.1:0`) |

## Team Deployment

Run a shared server for your team with Docker Compose (gta-pipeline + gta-mcp, ports `9888/9091/9092/8781`, per-member tokens via `GTA_AUTH_TOKENS=alice=gta_xxx,bob=gta_yyy`, `:admin` suffix for admins):

```bash
cp .env.example .env && docker compose up -d --build
```

Members connect from their own machines with a single `gta-agent` binary that pushes captures to `:9092` and hosts local decoder plugins via the registry tunnel (`GTA_TUNNEL=1` is injected for them). Full walkthroughs: [团队部署指南](docs/team-deployment.md) · [成员上手指南](docs/member-onboarding.md).

## Quick Start

**Prereqs:** Go 1.25+ · libpcap (Linux) / [Npcap](https://npcap.com/) (Windows)

```bash
make build        # gta-mcp + gta-pipeline + gta-plugin-dev → bin/

# terminal 1 — runtime plane (data path; start first)
./bin/gta-pipeline.exe -workdir . -log-format text

# terminal 2 — control plane (embeds the Developer Plane)
./bin/gta-mcp.exe -work-dir . -plugins-dir plugins -log-format text
```

Point your AI agent at `http://127.0.0.1:8781/mcp` (Streamable HTTP) or `http://127.0.0.1:8781/sse` (SSE), then have it smoke-test the stack:

```
start_capture(port=8984)      # session starts; keep the session_id
#   … generate traffic: go run ./examples/http/server   (+ ./examples/http/client)
get_session_status            # packets_in > 0 · decode_errors == 0
list_decoded_data(limit=50)   # decoded events — needs a decoder plugin, see below
```

`make test` runs the test suite; `make run-mcp` / `make run-pipeline` use `go run` for fast iteration.

## Plugin SDK

Plugins depend only on [gta-plugin-sdk](https://github.com/OwnSecurityGuard/gta-plugin-sdk) — a separate repo, zero coupling to gta internals. A plugin is **one Go binary + one `plugin.yaml` manifest**:

- the manifest declares the contract — capabilities, schemas, and state subjects (`plugins/godot-gateway/plugin.yaml` is a complete example)
- the host validates that contract at registration *and* per event at decode time
- `activate_plugin` launches the binary and injects `GTA_REGISTRY_ADDR` for you

The lifecycle is fully agent-drivable, with failure attribution built in:

```
create_plugin ──► build_plugin ──► activate_plugin ──► verify_plugin
                     │                 │                   │
                     └────────── explain_plugin ────────────┘
                     (attributes the most recent build / activate / verify failure)
```

Human-readable guide: [`docs/gta-plugin-development.md`](docs/gta-plugin-development.md).
